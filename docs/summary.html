FireScout - autonomous search scout for UK fire crews · AgentVerse 2026 Robotics · github.com/IyadZuberi/FireScout

User and problem

User: the Incident Commander (IC) and the breathing-apparatus (BA) crew at a building fire. Problem: crews search blind in smoke while survival falls by the minute (~75% if reached within 2 min vs ~28% after 8 min, ~1,000 rescues, Fire Engineering tally). Existing robots are teleoperated, heavy and cost $75k-$210k. FireScout is a 3-5 kg, ~$1.3-2.3k tracked scout placed at the door during the 2-5 min the crew needs to don BA. It has no floor plan and needs no operator.

Key features

  • Finds people in zero visibility: thermal blobs + tracker + logistic confidence; PIN only with two sensors (thermal ≥ 0.8 AND radar breathing ≥ 0.5); otherwise kept as POSSIBLE for the crew.
  • Maps an unknown building: 60 GHz radar ring + depth; tells furniture from walls by seen object height; map accuracy vs the hidden plan shown live.
  • Ranks who to rescue first (P1/P2/possible) from breathing, voice, distance to fire, heat, CO, O2; crew route visits P1 first.
  • Talks to conscious people: hears calls (4-mic bearing), then speaker: walk out if the measured route stays < 60 C and 1.5 m from fire, else stay put and stay low.
  • Adapts live: fire grows and spreads, smoke banks down, IC ignites objects or cuts the radio: it replans, retreats, re-checks, works offline.
  • Explains itself: every action is a decision card with the sensor reading and rule; METHANE (JESIP) report from its own map.
  • IC in control: STOP / RESUME / RECALL / search-room-first; IC confirm/reject trains the person detector (one SGD step).

System architecture

MuJoCo world (physics, fire/smoke growth, occupants) | noisy sensor models (sensors.py) v thermal 160x120 | radar 36 rays + breath | depth/IR mics (voice bearing) | CO, O2 | self-temp | radio AGENT on robot CPU (brain.py, numpy, 10 Hz) map -> perceive/track -> safety gate -> IC order -> verify person -> follow voice -> explore -> speed, speaker, routes, cards, METHANE | state + IC commands (localhost) IC console: browser three.js draws MuJoCo state only

Critical failure mode and safety

Critical failure: a person missed and an area wrongly reported "clear", so the crew skips it. Handling: the robot never declares an area empty (enforced in tests and the evaluation); unconfirmed warm bodies stay POSSIBLE with location and "crew must check"; scanned % is reported as coverage, not clearance; IC can reject false positives.

  • Safety gate (fixed, never learned): no-go cells > 250 C, retreat at 60 C self-temperature or 15% battery.
  • Radio loss: keeps searching, queues findings, returns to last radio contact.
  • Speaker policy only advises evacuation on a route it has measured as cool and clear of fire.

Limits

  • Simulation only; fire, smoke and heat are engineered models, not CFD. Voices synthesised.
  • One floor, no stairs or doors to open; planar robot base.
  • Breathing needs line of sight within ~2.5 m; radar does not see through rubble. RECALL_LIMIT
  • Priority labels support the crew; they are not clinical triage (UK guidance: medically led).
